# Street Memory: исправление чёткости и мобильной читаемости

Дата проверки: 10 ноября 2026. Исходная опубликованная версия: `be973754993679888a19ca5886d570d2c722d22e`.

## Причина проблемы

Это была совокупность трёх проблем, а не только низкое разрешение canvas.

1. `ResizeObserver` передавал CSS-размер поля непосредственно в `game.scale.resize()`. Физический размер canvas оставался равен CSS-размеру даже при DPR 2/3. Например, на 390×844, DPR 3, уровень 48 рисовался в 364×469 пикселей и затем увеличивался браузером в три раза по каждой оси. Измерения всех семи конфигураций до исправления показывают коэффициент 1.
2. Текст Phaser имел стандартное разрешение 1. Увеличение одного canvas без изменения растеризации `Text` сохранило бы размытые буквы. SVG загружались через `Image` с фиксированным intrinsic-размером 200×130 / 200×210 и после загрузки становились растровыми источниками для canvas.
3. Мобильные правила уменьшали важные надписи до 6–9 CSS px. Шесть машин помещались в один ряд; обозначения домов, направления и номера доков получались слишком маленькими. Светлые границы дорог и текст дополнительно снижали читаемость.

Проверен исходный код установленного Phaser **3.90.0**, в частности `core/Config.js`, `scale/ScaleManager.js`, `cameras/2d/Camera.js` и `gameobjects/text/Text.js`. В этой версии нет поддерживаемой настройки `GameConfig.resolution`; её добавление не решает задачу.

## Изменение рендера

- Сохранён `Phaser.CANVAS`, сглаживание включено, `roundPixels: false`. Pixel-art, CSS blur, фильтры резкости и ручное масштабирование контекста не используются.
- Логическая система координат поля остаётся в CSS-пикселях. Backing store рассчитывается из реального DPR. `Scale.NONE` с обратным zoom задаёт CSS-размер, камера с соответствующим zoom переводит логические координаты в физические пиксели. Компенсация центра камеры учитывает её округление при нечётных размерах canvas.
- `resize()` вызывается перед `setZoom()`. Это также устраняет обнаруженное в ходе проверки растяжение при DPR 1, когда после изменения высоты карточек Phaser оставлял прежний CSS-размер.
- Обновления размера объединены через `requestAnimationFrame`; синхронизируются bounds Phaser для корректного ввода. Отслеживаются `resize`, media query плотности и резервная проверка её состояния раз в 500 мс. Она инициирует перерисовку только при изменении DPR. Проверен случай, когда Chromium меняет DPR без событий.
- Каждый `Phaser.Text` явно растеризуется с текущей плотностью. SVG для сцены получают достаточный intrinsic-размер с сохранением `viewBox` и пропорций: на DPR 3 используются 400×260 для машин и 400×420 для домов. DOM-карточки используют SVG напрямую.
- Плотность ограничена DPR 3 и мягким бюджетом 5 млн backing-пикселей. Во всех обязательных конфигурациях используется полный нативный DPR. На существенно больших экранах плотность может снижаться; ниже одного backing-пикселя на CSS-пиксель она не опускается.

## Интерфейс и графика

- Мобильный парк размещается в трёх колонках, до двух рядов. Карточки имеют высоту 76–86 CSS px; выбор машины не требует попадать в маленькую иконку.
- Подписи карточек, номера доков и кнопок — 13 CSS px; второстепенная информация — не менее 12 px. Заголовки — 21–22 px. Убраны повторяющиеся декоративные подписи карты и футер на узких экранах; на коротких телефонах также скрыта подпись района.
- Все видимые активные кнопки в обязательной матрице имеют область не менее 44×44 CSS px. Сетка выбора улиц на телефоне содержит четыре колонки вместо восьми, кнопки высотой 54 px.
- Крупные символы домов — минимум 18 px, основные L/R — минимум 20 px. Направления рисуются контрастными векторными стрелками вдоль фактической дороги, а не округляются до одного из восьми Unicode-направлений.
- У дорог появились различимые тёмные края и светлая разметка. У автомобилей и домов усилены контуры. Символ машины перенесён внутрь светлого значка на кузове, чтобы он не перекрывал номер дока.
- Поле использует доступную площадь с отступами для домов. Докам подбирается свободное отображаемое положение без наложения на другие узлы и без новых пересечений дорог. Это отдельная функция отображения, не изменение уровня.
- Маленькие дублирующие метки L/R размещаются только там, где не перекрывают узлы и другие метки. На самых коротких дорогах они опускаются; крупная буква состояния и точная стрелка на знаке остаются. Это осознанный компромисс для плотных полей на коротком экране.

## Проверки и воспроизведение

```bash
npm run verify
npm run build
npm run audit:pages
npm run test:pages
# В отдельном терминале:
npm run preview:pages
# После запуска preview:
npm run test:visual
```

`verify` выполняет TypeScript, ESLint, 31 модульный тест, валидацию и воспроизведение 48 уровней, standalone / CrazyGames Basic / Full build, упаковку ZIP, аудит пакетов и материалов, аудит геометрии и 18 браузерных сценариев. Среди сценариев: реальный touch-ввод, Preview/Send, Undo, сохранения, Daily, звук, музыка, изменение размера во время поездки, координаты указателя при DPR 1/2/3 и смена DPR без CSS-resize. Production-сборка дополнительно проходит 11 Pages-сценариев.

`test:visual` открывает production-сборку в семи настоящих браузерных контекстах Chromium с заданными viewport/DPR и touch-эмуляцией. Для каждой конфигурации сохраняются полноразмерные снимки уровней 1 и 48 и кадры во время движения. Проверяются backing/CSS scale по обеим осям, шрифты, области кнопок, горизонтальное переполнение, ошибки и интервалы animation frames. Это проверки измерений и снимки для ручного просмотра, **не автоматическая оценка качества изображения по DOM**.

Дополнительно сняты все 48 полей на 375×667 DPR 2. Просмотрены контактные листы, плотные поля и полноразмерные снимки уровней 3, 15, 30, 41, 42, 47. Геометрический тест проверяет отсутствие наложений доков и новых пересечений дорог по всей кампании на шести разных размерах поля.

В GitHub Actions добавлен повторный запуск матрицы viewport/DPR перед загрузкой Pages artifact.

## Неизменность игровой логики

Контрольные суммы 13 защищённых файлов совпадают с исходными: `src/core/*`, `src/levels/*`, `src/app/progression.ts`, `src/game/Audio.ts`, `src/game/Music.ts`. [Список исходных SHA-256](visual-quality/protected-source-hashes.json). Уровни, генератор, правила движения, прогресс, Daily и формат/логика сохранений не изменены. Перемещение узлов относится только к координатам отображения.

## Границы проверки

- Проверено браузерное отображение с DPR 1/2/3 и touch-эмуляцией. **Физический Android/iPhone не подключён**; эти результаты не являются проверкой на реальном устройстве.
- Замер кадров сделан на этом компьютере, без искусственного CPU/GPU throttling. Он подтверждает отсутствие заметной деградации в проверенном окружении, но не гарантирует 60 FPS на любом телефоне. Сохранение PNG во время замера может само добавлять задержку.
- Safari/iOS WebKit, аппаратное энергосбережение, перегрев и системное увеличение шрифтов не проверены. Основная обязательная матрица — портретные телефоны, планшет и desktop; комфорт в экстремально низком landscape viewport требует отдельной проверки.
- Мягкий векторный стиль сохраняет естественное сглаживание, включая повороты машины; это не pixel-art.
- CrazyGames-сборки проверены локально, SDK — существующими браузерными сценариями с mock. Проверка в портале CrazyGames и публикация туда в эту задачу не входят.
- Новых функциональных регрессий в выполненных проверках не обнаружено. Окончательное подтверждение удобства на физическом современном смартфоне остаётся открытой частью приёмки.
